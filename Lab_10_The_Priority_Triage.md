### 🚑 The Mission
The USI Medical simulation lab just went into "mass casualty" mode: 50 patients have shown up at once, and the triage nurse can't just take them in the order they walked through the door. A patient in cardiac arrest cannot wait behind 40 people with a common cold. You've been asked to build the scheduling engine behind the triage desk — a **binary min-heap** that always surfaces the single most critical case next, in `O(log n)` time, no matter how many patients are waiting.

### Part A: The Proof Detective (50 Points)
**Instructions:** Answer the following questions in a separate document (PDF or Markdown).

1. **Array vs. Linked Tree — Index Formula Derivation:**
   Our heap will be stored as a flat Python list, not a tree of linked nodes.
   - For a 0-indexed array, **derive** (do not just state) the formulas for the **parent**, **left child**, and **right child** of the node at index `i`, using the level-by-level structure of a complete binary tree to justify each formula.
   - Using those formulas, if a patient is inserted at index `13`, walk through every index it compares against on its way up to the root during sift-up (assume it must travel all the way to the root).
2. **Proof by Induction — Level Count:**
   Prove by induction that a complete binary tree with `n` nodes has height `⌊log2(n)⌋`. State your base case explicitly (a heap of 1 node) before proceeding to the inductive step.

   > [!CAUTION]
   > **The Brutality Clause:** Question 2 is a formal inductive proof. A proof missing an explicitly stated base case receives an automatic **0** on that question, regardless of the correctness of the inductive step.
3. **Visual Tracing:**
   Starting from an empty min-heap (lower priority number = more critical), insert patients with priority values in this order: `5, 3, 8, 1, 9, 2`.
   - Draw the array state after **each** insertion (showing the sift-up swaps).
   - Draw the final array state after one `extract_min()` call (showing the sift-down swaps).
4. **PDC Reasoning:**
   Two ER intake stations are inserting new patients into the *same* shared heap at the same moment a doctor's station is calling `extract_min()` to pull the next case. If none of these three operations are protected by a lock, describe a specific sequence of events that could corrupt the heap or lose a patient record entirely.

### Part B: The Recursive Coder (50 Points)
**Instructions:** Complete the `insert`, `_sift_up`, `_sift_down`, and `extract_min` methods in the provided `test_triage.py`.

**Requirements:**
1. `insert(value)` must append the new value and call `_sift_up` to restore the heap property. `_sift_up` and `_sift_down` must be **recursive** — each call should perform at most one swap and then recurse toward the correct resting position; do not replace the recursion with a `while` loop.
2. The heap must be maintained as a flat Python list (array representation), using the index math from Part A.
3. `extract_min` must remove and return the highest-priority (lowest value) job, restore the heap property by moving the last element to the root and calling `_sift_down`, and correctly handle the case of a heap with zero or one elements.
4. **Base Case Required:** Both recursive sift methods must terminate correctly when a node has no valid parent/children left to compare against. Remember the **Brutality Clause** — a recursive method with no base case is an automatic 0.
5. **Verification:** Run the script using `python test_triage.py`. If you see the "Success Token," your implementation is correct.
